# 작업 흐름

이슈를 잡는 것부터 배포까지. 처음 한 바퀴를 돌 때는
[ONBOARDING.md](ONBOARDING.md) 의 "첫 PR" 절을 따라가는 쪽이 빠르다.

```
이슈 → 브랜치 → (마이그레이션 번호 예약) → 코드 + 테스트 → PR → 리뷰 1 approve → 머지 → CI → CD
```

---

## 1. 이슈

**1 이슈 = 1 브랜치 = 1 PR.** 이슈 없이 작업을 시작하지 않는다 — 브랜치명에 번호가 들어가야 한다.

이슈를 만들면 종류에 맞는 양식이 자동으로 뜬다 (`.github/ISSUE_TEMPLATE/`).

| 양식 | 쓸 때 |
|---|---|
| 기능 개발 | 새 API · 새 기능 |
| 버그 리포트 | 동작이 명세·기대와 다를 때 |
| 리팩토링 · 기타 작업 | 구조 개선 · 문서 · 설정 |

---

## 2. 브랜치

```
feat/203-privacy-consent
```

| | |
|---|---|
| 형식 | `{타입}/{이슈번호}-{작업내용}` |
| 타입 | `feat` · `fix` · `refactor` · `chore` |
| 주의 | **`#` 을 붙이지 않는다** — 셸과 일부 도구가 주석으로 해석한다 |

`main` 에 직접 push 하지 않는다. `main` 은 **운영 브랜치**다 — 머지되면 배포가 나간다.

---

## 3. 마이그레이션 번호 예약

스키마를 건드린다면 **코드를 쓰기 전에** 번호를 찜는다.
[`db/migration/README.md`](../src/main/resources/db/migration/README.md) 의 예약 표에 등록한다.

**PR 리뷰에서 번호를 정하지 않는다.** 여러 PR 이 동시에 열리면 반드시 충돌한다
(실제로 4회 났다 — [PITFALLS.md](PITFALLS.md#1-db-마이그레이션--사고가-가장-많이-나는-곳)).

---

## 4. 커밋

```
feat(recruitment): 지원서 임시저장 API 구현
```

`{타입}({스코프}): {내용}` — 스코프는 도메인 패키지명을 쓴다.

---

## 5. PR

본문은 템플릿이 채워진 채로 뜬다 (`.github/pull_request_template.md`).
**「리뷰 포인트」 를 비워두지 않는다** — 고민했던 지점, 대안이 있었던 선택을 적는다.
판단이 필요한 사항도 여기에 적고 넘긴다.

PR 본문에 `close #이슈번호` 를 넣어 이슈가 자동으로 닫히게 한다.

### 크기

**프로덕션 코드 500줄 이하.** 테스트는 세지 않는다.

```bash
git diff --numstat main...HEAD -- src/main | awk '{s+=$1} END {print s" 줄"}'
```

리뷰 부하는 프로덕션 코드에서 나오고, 테스트는 오히려 리뷰를 쉽게 만든다.
전체 변경으로 세면 테스트를 줄일 유인이 생겨 **규약이 거꾸로 작동한다.**

넘으면 쪼갠다. 자연스러운 분할선은 **① 엔티티 + 마이그레이션 → ② 서비스 + 컨트롤러** 다.

### 올리기 전에

- [ ] [리뷰 체크리스트](PITFALLS.md#리뷰-체크리스트) 자가 점검
- [ ] `./gradlew spotlessApply`
- [ ] `./gradlew build`

---

## 6. 리뷰

**교차 리뷰 1 approve 로 머지한다.** 머지 방식은 **Create a merge commit** — squash 하지 않는다.

리뷰를 받는 쪽이라면 지적을 그대로 반영하기 전에
**납득이 되는지 먼저 확인한다.** 이해가 안 되는 지적은 묻는다.
반영하면 무엇을 어떻게 고쳤는지 답글로 남긴다.

설계 판단이 갈린 지점은 [`docs/adr/`](adr/) 에 기록을 남기는 것을 검토한다.

---

## 7. CI — 머지 전에 돈다

`main` 으로의 push · PR 마다 `.github/workflows/ci.yml` 의 **세 job** 이 병렬로 돈다.
같은 브랜치에 연속 push 하면 이전 실행은 취소된다.

| job | 하는 일 | 무엇을 잡나 |
|---|---|---|
| **정적 검사** | 자격증명 커밋 여부 확인 → `./gradlew spotlessCheck` | `.env` 유출 · 포맷 위반 |
| **빌드 · 테스트** | `./gradlew build` (H2 라 컨테이너 불필요) | 컴파일 · 테스트 173개 · **ArchUnit 구조 규칙** |
| **스키마 검증** | MySQL 8.4 컨테이너에 Flyway 실행 → `ddl-auto: validate` | **엔티티만 바꾸고 마이그레이션을 빼먹은 것** |

포맷 검사가 실패하면 `./gradlew spotlessApply` 로 고친다.

> ⚠️ **스키마 검증이 못 잡는 것이 있다.** 매번 빈 MySQL 에서 시작하므로 전부 번호순으로
> 적용된다. **마이그레이션끼리 순서에 의존하는 문제는 드러나지 않는다** —
> 이미 돌아가는 dev·prod 에서만 터진다 ([PITFALLS.md](PITFALLS.md#순서에-의존하는-마이그레이션을-쓴다)).

---

## 8. CD — 머지 후에 돈다

`main` 에서 **CI 가 성공하면** `.github/workflows/cd.yml` 이 이어 돈다
(머지 자체가 아니라 CI 완료가 방아쇠다). 두 job 이 순서대로 돈다.

| job | 하는 일 |
|---|---|
| **이미지 빌드 · 푸시** | 컨테이너 이미지를 만들어 레지스트리에 올린다 |
| **배포** | Azure VM 에 SSH → compose 파일 전송 → 이미지 교체·재시작 → 헬스체크 |

CD 는 **진행 중인 실행을 취소하지 않는다** (CI 와 다르다). 배포 도중에 끊으면
중간 상태가 남기 때문이다.

배포 대상은 `api.getit.io.kr` 다. 배포가 안 될 때의 대응과 운영 작업은
[DEPLOYMENT.md](DEPLOYMENT.md) 를 본다.

## 함께 쓰는 파일을 건드려야 할 때

`SecurityConfig` · `application*.yml` · `global/dto` · `GlobalExceptionHandler` ·
`User` · `Generation` 엔티티는 전 도메인이 공유한다
([ARCHITECTURE.md](ARCHITECTURE.md#함께-쓰는-파일--바꾸기-전에-물어본다)).

혼자 고치지 않고 **이슈로 요청한다.** 불가피하게 함께 바꿨다면 PR 본문의
해당 섹션에 무엇을 왜 건드렸는지 적는다.
